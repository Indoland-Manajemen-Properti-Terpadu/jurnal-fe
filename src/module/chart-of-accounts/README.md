# chart-of-accounts

Chart of accounts: account list, add/edit account forms, account detail query, settings (import, export, restore) and the cash mapping tab. Task 6 PR (a) moved everything here from `GeneralJournal`; PR (b) extracted the account rules and split the add/edit forms; PR (c) made the account mutations throw, fixed the file download, split the last large files and moved every string to i18n.

- **Public API (`index.ts`):** `useJournalAccounts`, `getJournalAccounts`, `JournalAccounts`, `useDeleteAccount` (was `useDeleteJurnalAccount`), `useDetailAccount`, `archiveAccount`, `accountDetailData`, `DetailAccountModel`, `useAccountStore`, `CashMapping`, `canArchiveAccount` and `canDeleteAccount` (used by the account ledger menu). The three route pages are imported by the router from `presentation/pages/*` directly (exporting them from the index creates a cycle with `beginning-balances`).
- **Layout:** `domain/` (types), `infrastructure/` (`accountApi`, `accountDetailApi`, `accountSettingApi`), `presentation/{pages,components,hooks}`.
- **Routes:** unchanged; the router imports the three pages from the index.
- **Endpoints:** `API_ACCOUNT.*` (list, detail, archive, delete, category, create, update, import/export/restore).
- **State:** query keys `['accounts', showArchived]`, `['detail_account', id]`, `['category_account']` and `['category_info', id]`; selection store `useAccountStore` (zustand). Add, update, delete, import commit and reset invalidate `['accounts']` (the dead `journal_accounts` and `head_accounts` invalidations were removed, R5).
- **Cash mapping:** `CashMapping` is a mock (static data), kept as is.
- **Domain rules (`domain/accountRules.ts`, pure, tested):**
  - I5 normal balance: `resolveEffectiveDebit` goes through the kernel `isDebitNormal` (`@/lib/accounting`): category `isDebit` (debit when unset), flipped for a contra account. No keyword fallback on the create form.
  - I6 create: name at least 3 characters (`validateCreateName`), code and category required, a Sub account requires `headAccountId`, a single account with a restricted scope needs members (`isHierarchyAndAccessValid`). Edit keeps a weaker name rule (non-empty, `validateEditName`): the 3-character rule is create only, kept as is. `isCashBankCategory` auto-sets `isBankAndCash` from category `KB` or a name with "kas"/"bank"; `getCategoryPrefix` (kernel `accountTypes`, re-exported) is the code prefix map by category.
  - I7 locked accounts: `isAccountSelectable` (used by the account table), `canDeleteAccount`, `canArchiveAccount` and `canChangeCategory` (the edit form disables the category and hides the hierarchy card). Delete and archive are only reachable through the selection, so the predicates are not called there yet.
  - Also pure: `buildAccountPayload` (one payload for create and update), `mapAccountDetailToFormState`, `groupCategoryOptions`, `ACCOUNT_PRESETS` (quick templates; the short keyword `ap` also matches "Pendapatan", kept).
- **Form layout:** `presentation/components/account-form/` holds the sections of both pages (`AddAccount*Section`, `EditAccount*Section`, `AccountPresetPicker`, `AccessMemberSelects`); `hooks/useAccountFormOptions` and `hooks/useAccountPlacementState` are shared. The two pages render different markup (add is the stepped layout, edit the compact one), so only logic and the member selects are shared.
- **Errors (R3):** `createAccount`, `updateAccount`, `deleteAccounts` (`infrastructure/accountApi`), `archiveAccount` (`accountDetailApi`) and the settings calls use the default `apiClient`, so an HTTP error rejects and reaches TanStack Query. Before, `post/patch/del` returned the error response, so a failed save showed the green toast and navigated away. Failure toasts show the server `message` when there is one. Endpoints, payloads and query keys are unchanged.
- **Downloads (R7):** the template and export downloads use `apiClient.get(..., { responseType: 'blob' })`; an HTTP error rejects (and a status of 400 or more throws) instead of saving the error body as `.xlsx`.
- **Large files:** `AccountListPage` uses `AccountStatsCards`, `AccountListHeaderActions` and `domain/accountStats`; the import wizard is `ImportAccountWizardModal` (state) plus `ImportUploadStep`, `ImportPreviewStep`, `ImportDoneStep` and `domain/importPreview`; `SettingAccountModal` renders three `SettingActionCard`s (themes in `settingActionThemes`).
- **i18n:** namespace `chartOfAccounts` (`src/i18n/locales/{id,en}/chartOfAccounts*.ts`, split into `List`, `Form` and `Guide` files that one `chartOfAccounts.ts` spreads; key-parity test in `src/i18n/locales/chartOfAccounts.test.ts`). Groups: `list`, `table`, `settings` (modal, import, export, restore, toast, error), `form` (add form and preview, keys moved from `journal`), `edit`, `guide`, `validation`, `presetNames`, `toast`, `cashMapping`. Domain validators return a key such as `validation.nameMin`; the page translates it. Preset keywords (`ap`, `kb`, `kas`...) stay Indonesian because they match backend category names.
- **Known gaps (not changed, for the owner to decide):**
  - Edit only requires a non-empty name (`validateEditName`); the 3-character rule is create only.
  - The preset keyword `ap` (receivable) also matches "Pendapatan" and other names containing it.
  - `CashMapping` is a mock: static rows, selects that do nothing, no HTTP. It is translated like the rest but still mock data.
  - `canDeleteAccount` and `canArchiveAccount` are called by the `account-ledger` header menu; the list itself only reaches delete and archive through the selection (locked rows cannot be selected).
  - R7 (open): the "import bank statement" item of the list header menu navigates to `routes.generalJournal.bankStatementDraftImport` with the `:idAccount` placeholder unfilled, because the list has no account. The draft page then takes the literal ":idAccount" as the account id and only shows rows when an earlier upload left a draft in `localStorage`. Options: hide the item from the list (the import modal in the reconciliation tab of the cash/bank account page is the working entry), or ask for an account first. Not changed; pinned by `AccountListHeaderActions.test.tsx`.
  - Strings that were English in the code (delete toasts, `CashMapping` headers, "Unnamed category" and "Unnamed Role") keep that text as the `id` value; they still need an Indonesian wording.
  - `GetCategoryAccount` and `useGetCategoryInfo` still use the swallowing `get` helper; archiving from the detail pages refetches `['detail_account', id]` but not `['accounts']`.
  - The journal namespace keeps the old form keys (other modules may use them); this module no longer reads them.
