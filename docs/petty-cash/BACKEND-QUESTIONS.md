# Pertanyaan untuk Tim Backend: Modul Kas Kecil

Dari tim frontend, untuk integrasi `/v1/petty-cash` ke Jurnal FE. Dasarnya: collection "Jurnal Proapps - Kas Kecil", PRD Kas Kecil, dan satu putaran penuh semua alur di Demo Site (hasilnya di [`API-REAL-SHAPES.md`](API-REAL-SHAPES.md)).

**Status 2026-11-04: backend sudah menjawab** (dokumen `JAWABAN_BACKEND_KAS_KECIL.md`, dasar kode `jurnal-be` branch `main-backend`, commit `88e8196`). Jawaban itu **belum dicocokkan dengan build Demo Site**, dan backend sendiri mencatat beberapa temuan FE tidak cocok dengan kode itu (audit `APPROVE` lawan `APPROVE_BM`/`APPROVE_CF`, `stack` di respons, jawaban 5), jadi build Demo kemungkinan lebih lama. Isi jawaban dirangkum di bawah; penjelasan teknisnya ada di [`API-CONTRACT.md`](API-CONTRACT.md) bagian 9.

Nomor di sini mengikuti dokumen pertanyaan ini (40 butir). Dokumen jawaban memakai 38 nomor yang bergeser setelah butir 23; pemetaannya ditulis di kolom "Jawaban".

**Status**

- `DIKETAHUI`: perilaku sudah pasti, tinggal diikuti FE.
- `KEPUTUSAN`: butuh keputusan bisnis atau produk sebelum ada yang diubah (lihat [FOLLOW-UPS.md](FOLLOW-UPS.md)).
- `DIPERBAIKI BACKEND`: celah yang diakui backend, belum dikerjakan.
- `DI LUAR BACKEND`: tindakan tim ops atau pemilik collection.
- `PERLU CONTOH`: backend meminta data dari FE.

## Yang sudah terkonfirmasi benar (tidak perlu dijawab)

Jurnal selalu seimbang. Saldo GL akun kas kecil tetap sebesar pagu. Persamaan `pagu = cashBalance + pendingVoucherAmount + outstandingAdvanceAmount - unsettledVariance` berlaku setelah setiap langkah, dan laporan rekonsiliasi `isOk: true`. Uang disimpan sebagai bilangan bulat rupiah. Pajak voucher ditambahkan di atas nilai baris. Kantong (pocket) hanya merinci buku kas dan semuanya memakai satu akun kas kecil; pindah antar kantong tidak membuat jurnal.
